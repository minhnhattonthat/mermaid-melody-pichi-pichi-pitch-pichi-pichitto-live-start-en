# Skill gotchas

One line each: the skill reference file it belongs in, then the fact.

- scripts/fetch_emu.py: `gba-bios` 404s; retrobios renamed the file to `bios/Nintendo/Game Boy Advance/GBA_bios.rom` (same SHA-1 300c20df...). Downloaded by hand with curl into `tools/mesen/Firmware/gba_bios.bin`; the BIOS table in fetch_emu.py needs the new path.
- SKILL.md / context-mode: with the context-mode plugin active, plain `cat`/Read of long reference files gets truncated to an index; read them through `ctx_execute` instead.
- references/emulator-qa.md: Mesen (portable) keeps a GBA battery save in `tools/mesen/Saves/<rom>.sav` across emu.py runs without `--sav`, so first-boot screens (name entry) appear once and never again; pass `--sav` with a blank file (32 KiB of FF) to reach them.
- references/emulator-qa.md: watch.lua logs one line per PC, so a loop or DMA writing a whole glyph shows only its first write (often 0); diff two ppu dumps to see what really changed.
- references/emulator-qa.md: GBA `.io.bin` BG scroll registers are write-only; the dump read back 48,48 for every BG while the real scroll was 0. Do not compute map positions from them.
- references/pipeline.md (Recon, code = font cell): template matching against MS Gothic failed on this bold 2bpp-antialiased 12 px font (<30% right, even greyscale + bbox-centred); a name-entry charset table (code -> glyph in gojuon order) gave every kana for free, and reading 300 kanji off 16-wide labelled sheets plus word-list checks for look-alikes was faster.
- references/pipeline.md (Extract): bytecode with call/goto/jump-table pointers into the text (F8/F9/FA here) needs units split at every pointer target and the pointers rewritten on repack; jump tables indexed at runtime have no length, so read entries until the lowest target seen (worked for every table in this ROM, checked by an op/arg-conflict coverage pass).
- references/graphics.md (Survey): with no reviewer subagent (Orca worker), `codex exec --sandbox read-only -i sheet.png ...` reviewed 104 sweep sheets in 18 calls (tools/codex_review.sh); it misread ~5% of hex labels and replies lack a final newline (concatenate with `awk 1`).
- references/emulator-qa.md (Debug tool): look for a scene dispatcher in AgbMain's loop first (here `table[u8 id]`, table of 43 pointers); writing the id from Lua warped to every scene and id 0 turned out to be a leftover debug menu (message viewer, episode select). Took ~20 min vs. hours of ramsearch.
- references/emulator-qa.md: ramsearch across runs that all start from the same savestate matches uninitialised/random RAM as "stable per screen"; compare runs from different starts or go to the code.
- scripts/emu.py: rows of a TSV edited with the Edit tool lose a tab if old_string ends in `\t` and new_string does not re-add it; rewrite small TSVs whole and keep a parse test (tests/test_scenes.py).
- references/platform-gba.md (Fonts): BL reaches only +-4 MiB, so hooks in free space at 0x09FDxxxx can't be called from 0x0800xxxx; detour with `ldr rX,[pc]; bx rX; .word target` inside the patched prologue (replay it in the hook) or repurpose a literal-pool word only one ldr uses, and return with an absolute `bx`.
- references/platform-gba.md (Fonts): this engine's blitter draws at x & ~3 and overwrites a 12 px window, and allocates fresh VRAM tiles per blit; a VWF needs a RAM-composed cell (previous glyph's spill OR shifted glyph) and must free the tiles of re-blitted columns, else the tile pool wraps and garbles earlier text. Only free columns the previous blit on the same line mapped: scrolled boxes leave stale map entries.
- references/pipeline.md (Width gate): the auto-wrap here tests px + fixed spacing (12) > W*8 before each glyph, not the glyph's real width: the budget is 'last glyph starts at <= W*8-12', not 'line width <= W*8'.
- references/pipeline.md (Width gate): story speech bubbles are sized per message by event-script data (op 0x4009), not by the text; widening W/col in that data draws a correct bigger bubble, so auto-grow in the build beats per-bubble limits.
- scripts/lua (keystone): assembling a prefix to get label offsets includes the auto-appended literal pool, so offsets come out wrong; put a fixed branch table at the top of the blob instead.
- docs/re/compression.md wording: the free space at 0x1FDF760.. is zero-filled in the dump (FF only in the trap-test build).
- references/emulator-qa.md (Visual QA): a text box that looks translucent or cut at its edges in one shot can be a scene fade-out in progress; look at the frames before it before chasing layers/windows (cost a probe and two test builds here).
- assets/batches.py (wrap): split chunks after page codes too ({FA:06}/{wait}) and measure the line before the code; otherwise "word{FA:06}Next" never wraps and every translator hand-inserts `\n` (fixed here in tools/batches.py, worth porting).
- assets/batches.py (glossary check): compare terms against the English with whitespace folded, or a wrap break inside "Mermaid Beads" fails the term.
- references/translation.md (Validation): a name inserted by a call can't take a glued plural ("{call:Mermaid Princess}s" draws "Princesss"): lint `{call}s` when the called text ends in s, and let the check accept a call written out as its own text. 19 lines in 5 batches hit this.
- Claude Code context-mode plugin: whole-file Read refused above ~4 KB, for subagents too; tell translator/reviewer agents to read with offset/limit in the dispatch.
- references/pipeline.md (Width gate): calibrate the fit lint on the original script first (Japanese must give 0 errors); it exposed wrong ranges (lyrics vs link messages), no-wrap credits, scrolling bubbles and false event-stream hits past its end.
- references/translation.md §Review: with no reviewer subagents (Orca worker), `codex exec --sandbox read-only -o <batch>.report.md` on the pairs file works as the independent pass and saves the report (tools/codex_tl_review.sh); it found 1 Critical + 40 Important the first pass had filed as Minor or missed.
- references/pipeline.md §Checks: a write log needs no per-writer instrumentation: diff the ROM around each build stage (numpy, ~1 s for 32 MiB) and tag runs with the stage; overlap/orig checks then catch stages clobbering each other (tools/writelog.py).
- references/graphics.md: GBA Konami kcomp games: a sweep that decodes each pointer as one stream garbles blocks that are chains of fixed-size streams (0x800 each, caller decodes chunk by chunk); check a block's size against 0x800 multiples + small overrun before trusting its sheet.
- references/graphics.md §Edit and re-import: a PNG round trip through a palette that repeats a colour keeps the original index wherever the new pixel has the shared colour; erased text drawn under another palette then reappears (difficulty bubbles, OBJ pal 12 vs 8). Cut the group palette from one with 16 distinct colours.
references/graphics.md: a 0x800 kcomp chain can be panels (128x32 each) laid 2 across in OBJ VRAM; a word straddling panels shows as residue when the block is drawn as one 16-tile-wide sheet (layout objWxH*N/R in tools/gfx.py).
- references/graphics.md: text on a BG map is often boxed in by cells of other palettes (art) and by shared tiles (blank tile 0): an English redraw can only use banner-palette cells (or ones whose palette holds near colours) and tiles used once; check both per pixel before writing (tools/gfx_bg.py + gfx_solo.py here).
- references/emulator-qa.md: a PPU dump keeps BG control registers of layers DISPCNT has turned off, with stale VRAM behind them; read DISPCNT before picking a layer.
- references/emulator-qa.md / graphics: a panelled OBJ atlas (obj16x4*N/2) keeps its sprites on 2D VRAM rows (row = tile // 32), not on the 32 px panels; gfx_where-style rects that assume 16-tile rows mislead there.
- references/platform-gba.md: a sweep of resource tables can miss streams; logging the decoder entry (r0 dst, r1 src) with an exec hook (tools/lua/kcomplog.lua) finds the source of any VRAM tile in one run.
- references/graphics.md: a run of compressed chunks can each have a pointer AND be read as one chain from the first (plus pointerless tail chunks); a shorter in-place re-encode of one chunk shifts the rest. Re-encode the whole run as one chain and repoint every chunk start.
- references/platform-gba.md: an IO register (mosaic 0x0400004C) written from a Lua frame hook gets overwritten by the game's VBlank copy from a RAM shadow; watch the register, then zero the shadow in an exec hook on the copy (tools/lua/nomosaic.lua).
- references/graphics.md: a BG map that is neither raw nor a known compressed block can be a tiny run stream read by IWRAM fill/copy calls: log the fill routine's registers (tools/lua/execlog.lua) and a register walking ROM in fixed steps points at it.
- references/graphics.md: to find a sprite's piece list, watch writes to the OAM shadow (DMA source from dmalog), then execlog the writer: the list pointer is a register. Offsets to lists can sit in packed 3-byte frame entries (u8 + u16, odd addresses): a pointer/offset search filtered to even addresses misses them.
- references/emulator-qa.md: a play.py step savestate made on the English build loads with the original ROM in `emu.py --state-in` (GBA, Mesen), so a screen reached by turn-by-turn play can be PPU-dumped on the original for vramfind; the next screen loads fresh from that ROM.
- references/graphics.md: once one run-stream map record is known, find the others by decoding every offset nearby and matching each dumped BG map (seconds in Python); rewriting a record in place must not grow it: edit uniquely-used tiles in place and allocate new tiles only for edited shared cells (prev+1 keeps increment runs).
- references/graphics.md: GBA BG text cells with per-cell palettes may have no palette slot free for a new ink colour (all 15 used by the art); move the cell to a palette that has the colours (rewrite its map entry, remap the cell's other pixels) rather than recolouring per pixel, which comes out blotchy.
- references/platform-gba.md: one engine can have two run-length map formats behind the same writer (here op byte with n LE u16 literals vs a BE single literal): read the decoder (IWRAM copy, ARM) before assuming a known record format.
- references/platform-gba.md: a VWF that hooks one drawchar mode misses the others: this engine draws in-song dialogue, credits and furigana runs in an 8 px mode (flags bit 0) through a second blitter and an 8x12 kana font, so English codes came out as kana there; log each glyph's path (tools/lua/pathlog.lua) over a song and the credits before calling the VWF done.
- references/platform-gba.md: when a VWF frees and reallocates tiles, check every consumer that assumes tiles are allocated from slot 0 contiguously (here a lyric predraw DMA-copies only slots 0..103 per line): rewind the allocator cursor to the lowest freed slot.
- references/emulator-qa.md: bold typesetting (core pixel + 1 px to the right) fills the 1 px gaps of m/w/M/W into solid blocks; keep wider bold variants of those glyphs in the typeset font.
- references/translation.md: a Japanese line longer than its box is not a width budget: engines that char-wrap kana let the original run 40-76 kana on one line, and English wrapped to that width splits mid-word ("lov/e"); budget unknown boxes at the box width (log W/H of every box shown in tours, tools/msgboxes.py) and wrap to it.
- references/translation.md: a speaker-name tag that closes without a newline (inline name, here in-song dialogue) shares the first line: the fit lint must count it, and the English needs a separator ("Lucia: ") where the Japanese used 【】.
- references/emulator-qa.md: a codex verdict runner that greps `codex exec -o FILE` output must delete FILE first: a failed run leaves the previous tour's file and its stale verdicts get recorded.
