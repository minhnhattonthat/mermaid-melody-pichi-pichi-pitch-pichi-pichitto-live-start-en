# English font and VWF (phase 5)

## Font
- `fonts/en12.txt` (drawn for this project): 1-px black core, `tools/enfont.py` adds a dark-grey bold pixel right of
  each core pixel. Cell rows: caps 2-8, x-height 4-8, descenders 9-10. Advance = core width + 2 (bold + 1 px gap).
  Average ~5.5 px, so a 216 px line holds ~38 characters (Japanese: 18).
- Glyphs overwrite single-byte slots of the 12x12 font (`tbl/en.tbl`, generated by `enfont.py tbl`): the English
  build draws no Japanese from the script. Digits keep the slots of the name charset / number printer
  (0xB4 0x85 0x9D 0x97 0xA2 0xBD 0xB9 0x88 0xDC 0xA1 = 0-9). Reserved: 0x00 (the blitter's blank special case, no
  compositing) and 0xAC (name charset 0x15 `⇔`, special-cased in drawchar). Attribute bits 14/15 (0x187E2B8) are
  cleared for every English slot (bit 15 = other drawchar path, bit 14 = alternate cell in the blitter).
- **verified**: torture line in msgview (`build.py --qa 2873=...`), every glyph renders, neighbours intact.

## Engine facts (read from the code)
- drawchar 0x080056CC (mode 0 = FD 00): x = [obj+0x20]*8 + [obj+0x2B] (u8 px), row = [obj+0x21] + s8 [obj+0x25]
  (tile rows, line pitch 16 px), colour [obj+0x2D], blitter stack args [obj+0x30] (map buffer: <= 1 -> 0x03002DB0
  + n*0x500, else [0x03002A2C]) and [obj+0x2E] (tile owner). Advance += [obj+0x2C] (12; FD bit0 = 8, bit7 = 16).
- Blitter 0x08004E68 draws a 12x12 cell into a 16x16 area at x & ~3 only (sub-tile offset 0 or 4), overwriting the
  whole window with background. Offset 4 reuses the left column's tiles when its map entry is > 0x3F; otherwise it
  allocates 4 tiles (2 columns x top/bottom, ids t..t+3, map = 0xF000 | (t + 0x40)); offset 4 allocates 2.
- Tile allocator 0x08004A00(n, owner): usage bytes at 0x03002A42 + t (= owner + 1), ring search from [0x03002A38];
  pool 0..0x1C0 here. When full it returns a slot in use (garbage on screen). 0x080047A0 clears a map rectangle and
  frees its tiles.
- Auto-wrap: before a glyph, if flag 0x40000 and s8 [obj+0x24] (= px >> 3) >= [obj+0x32] (box width in cells), the
  line breaks (0x080076EC). A glyph that starts inside the box may run up to 8 px past it.

## VWF patch (`tools/vwf.py`, applied by `build.py` to every English build)
- drawchar prologue -> `ldr r2,[pc]; bx r2; .word detour` (BL cannot reach 0x09FDF800 from 0x0800xxxx). The detour
  takes the English path when the code has a width, mode bits (flags & 0x13) are 0 and spacing is 12; anything else
  replays the prologue and jumps back to 0x080056D4.
- English path: compose the cell in RAM (0x02033700, 64 bytes: +0 cell override, +4 obj, +8 row, +12 last x,
  +16 colour, +20 free limit, +24 cell): previous cell >> 2*(window delta) OR glyph << 2*(x & 3), when the same object
  draws on the same row moving right; a colour change moves the glyph to the next 4 px boundary (else up to 2 px of
  the previous glyph would be redrawn in the new colour). Then free this owner's tiles under the columns the
  blitter will remap, but only columns the previous blit on this line mapped (a scrolled box leaves stale map
  entries that point at tiles shown elsewhere), call the blitter, advance by the width table (0x1FDFC00, u8 per
  code 0x000-0x5FF).
- Blitter font-address computation (0x08004F46) -> `ldr r1,[pc,#0x4C]; bx r1` through its own pool word 0x4F94
  (no other user): use the RAM cell when the override is set (and clear it), else font + 36*code.
- Mode 1 (flags bit 0, spacing 8: in-song dialogue boxes opened from the gameplay script, credits/profile `{FD:01}`
  runs, msgview) normally draws through a second blitter 0x08005204 with an 8x12 kana font at 0x09878BE8 (24 bytes a
  glyph), so English codes showed as kana there. The detour sends mode 1 to the English path too, except message
  ids < 7 (debug menu 4 keeps its kana, D13). **verified** EP 1 song (work/qa/gp8).
- Lyric predraw 0x0801E868(dest, msg): opens slot 0 W 28 H 2, draws the whole line, DMA-copies map row 0 (0x80 bytes
  from 0x03002DB0) and **only pool slots 0..103** (VRAM 0x06000800, 0xD00 bytes) to `dest`, then resets the pool
  (0x080048B0). The allocator 0x08004A00(n, owner) searches n free slots from the cursor u16 0x03002A38 (pool
  bounds u16 0x03002A3A..0x03002A3C) and moves the cursor past them, so freed slots were never reused within a line
  and long English lines ran past slot 103 (missing letters, stale tiles). free_col now also moves the cursor back
  to the lowest slot it frees. **verified** EP 5 song (work/qa/ly5b_strip.png).
- RAM 0x02033700..0x0203373F: never written in 50 warp scenes x 900 frames (watch.lua); 0x03007600 is hit by a DMA.

## Boxes (width gate, measured with `tools/lua/boxlog.lua` on the marker build: `regen.py build/marker.gba --script tools/lua/boxlog.lua`, story EP runs in work/p5/boxep)
Wrap rule: a glyph is drawn only if px + 12 <= W*8 (0x08007688 uses the fixed spacing, not the glyph width), so
**the last glyph of a line must start at px <= W*8 - 12**; else the engine breaks the line there. Lines per page =
H / step. textobj_open(slot, msg, col, row, W, H, flags) = 0x080046E4 (24 callers); setbox = 0x080046C8.

Event scripts (raw u16 stream, 0x1F5C660..~0x1F73000): word = len<<12 | op (len counts the word), handlers at
0x0804D3DC (105 ops). Op 9 len 4 = set bubble (col<<8|row, W<<8|H, tail<<8|?), op 10 len 3 = show message
(arg & 0x7FFF) + 0x500 in the last set bubble. A linear walk desyncs in data blocks (2425 skips) but finds 806
messages, each with exactly one box. 1456 used ids were not observed in any box yet (mostly 7-255, 306-511,
540-1027 lyrics, 1029-1280, scattered 1330-2473): give them the narration limit (196 px, 3 lines) as a **guess**
until a tour sees them.

## Width gate (`tools/boxes.py`, tests `tests/test_fit.py`, run by `tools/check.py`)
- `boxes.bubbles(rom)`: the walk above, stopped at 0x1F67000 (past it the stream is data and gives false bubbles for
  1330-1335): 799 message ids (1480-2471) with col/row/W/H. W 6-28, H 2-14 (1903 = H 14), col + W <= 29.
- Budgets: bubble = 212 px (any bubble may grow to W 28), lines H/2; ranges: credits 80, 88-98 = 220 px (the Japanese
  runs to 216: no auto-wrap there, screen edge), lyrics 256-305 and 512-1023 = 180 px (= longest Japanese line),
  link messages 1024-1030 = 212, narration 1281-1329 = 196 / 6 lines, 0-6 not checked; the rest a guess (warn only).
  A unit with no message id takes the budget of a unit that jumps to it.
- Measuring: `{call}`s are inlined (speaker names); text between `{FA:0C0008}` and `{FA:0C0088}` is the name tag
  (its own window, not counted); `{FA:06}` and `{wait}` start a page; `{FA:11..}` (credits column move) starts a line;
  `{FD:01}` = 8 px monospace, `{FD:80}` = 16; trailing spaces don't count; F6 names guessed 60 px, FB numbers 7 px a
  digit (shortcuts in boxes.py).
- **verified** calibration: the Japanese script gives 0 errors. Lines: 71 Japanese bubble pages run 4-5 lines in an
  H 6 box (the box scrolls), so extra lines are an error only past both H/2 and the Japanese unit's longest page.
- Auto-grow (`boxes.grow`, in `build.py` for English builds): W = ceil((need + 12) / 8) up to 28, col moved left so
  col + W <= 29; never shrinks. **verified** EP 1: msg 1531 (col 4 W 20) at col 2 W 27 and col 1 W 28, msg 1533
  (col 6 W 18) at col 3 W 26 draw clean, tail kept (work/p5/g1.png, grow4.png). A bubble that looks translucent at its
  edges in a shot is the scene fade-out, not a layer problem (checked: no windows, no blend at that frame).

## Known limits
- msgview's debug box with more than 7 lines (no page break) garbles earlier rows while the 8th+ line draws; real
  pages are <= 4 lines (`{FA:06}` page breaks) and the story box shows clean. Not chased further.
- Text objects in modes 1-3 (FD 01/02/03) or with spacing != 12 stay monospace (original path).
